For each message-list saga, the object is freshly constructed with exactly those three own keys, passed to the corresponding `MessageServices` method, and assigned by the endpoint method to Axios `config.params`. This establishes local own properties, not guaranteed literal wire keys: Axios `#5675` omits null/undefined values, while its `#5676`/`#5677` serializer recursively represents array/object values as nested bracketed query keys. The disassembly does not establish runtime value types for `page` or `term`; no `optional` flag is inferred because the local own-property writes are unconditional. Scalar `perPage=50` is a traced client value, not an API default.

For questionnaire `required`, the field name is a client-observed body key copied from the source question object. It is not a claim about whether the server requires that key.

The two questionnaire routes are anchored in the original disassembly: #39484 stores #39491 at `+0x161–+0x166`; #39489 invokes it with its freshly constructed five-key object at `+0x49`. #39490 invokes captured handler #39491 at `+0x82` in one branch (1592151–2154); its direct-import branch also accesses dependency slot 15, resolves the action export and invokes it with the six-key body (`+0xc9–+0xe2`, 1592168–2178). The imported module identity is established by registrations, not an export-name match: #39481 is registered as module 4125 with slot 15 = module 2286 (20750–20753); module 2286 is factory #26464 with dependency `[1,2287]` (11555–11558); module 2287 is factory #26485 (11560–11563). #26464 exports action creator #26474, which returns thunk #26475; that thunk forwards each body to the `fillQuestionnaireQuestion` service entry bound to #26494 by QuestionnaireService #26486 (1028044–1028110, 1028334–8371, 1028600–8649), which posts it (1028788–8815). Keep the client body variants distinct; their observed shape does not establish server validation.

## Partial projections; remaining data unresolved

- `CreateEvent` (#25405): saga #25377 calls helper #25369, then forwards the result as POST data. The helper begins with `Object.assign({}, input)` and conditionally rewrites truthy `start_time` and `end_time` using timezone conversion plus `.utc().format("HH:mm:ss")` (#25369, `eliis.hasm` 994508–994589). Those partial keys are optional because absent incoming properties are not added. All other incoming event properties remain opaque.
- `UpdateEvent` (#25407): saga #25380 applies the same helper to `selectedEvent` before forwarding it as PUT data. It reads `kindergarten_id` and `id` to form the URL, but those URL reads do not establish body keys; only the helper's conditional time projections are recorded.
- Draft writes `CreateDraft` (#25243), `SaveDraft` (#25245), and `DeleteDraft` (#25247): data arguments are forwarded (the DELETE function puts its second argument into config `data`); their complete caller-side constructors were not established in this bounded slice.

For `FillPollQuestion`, `other_id` is always assigned as a local own property, but its value is `undefined` when `options.find` has no result. Axios `#5842` JSON-stringifies plain-object request data, so that undefined-valued property is omitted from the serialized body in that case; no wire-presence guarantee is made. `skip` remains exclusive to the alternate `submitDashboardPoll` branch.

No HTTP calls, login attempts, or private-record access were made. This candidate JSON/Markdown pair, `evidence/research/communications.json`, and `evidence/research/communications-notes.md` were the only files changed for this integration; the independent review report and generated artifacts were left untouched.

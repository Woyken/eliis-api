## Findings

### 1. [High] `GetGuardianFeed` query date branch is reversed in the evidence and capability docs

`evidence/research/children-diary-files.json` (the `GetGuardianFeed` query evidence), `evidence/guardian-batch/diary.json` (request candidate and `querySemantics`/`dateTimeSemantics`), and the generated `GetGuardianFeed` row in `docs/GUARDIAN-CAPABILITIES.md` say a truthy `diaryNextDate` is formatted as `YYYY-MM-DD` when page is not 1, page 1 copies it, and a falsy value may be assigned as undefined.

That is opposite to the branch in original `#25515` at lines 1000445–1000458. A falsy date branches to the formatter block; otherwise the captured page is compared with 1. `JStrictNotEqual` at offset `0x59` jumps to `0x7b` when page is not 1, skipping the formatter at offsets `0x5d–0x76` and preserving the truthy selected value. When page is 1, execution falls through to the formatter; the call at `0x5d–0x76` is made with the `undefined` argument loaded at line 1000430, not the selected `diaryNextDate`. The subsequent object write at 1000457–1000458 always assigns the resulting value to `params.date`. `#25632` forwards that object as Axios `params`; `#25516` stores page separately in the action payload.

**Required correction:** rewrite the candidate, request evidence, date/pagination capability text, and rendered table to match the branch above. Do not claim the formatter result is a particular date or that the falsy branch emits `undefined` unless the imported formatter's behavior is separately traced. Retain query value type `unknown`, open query passthrough, and all server date/acceptance semantics as unknown.

### 2. [Medium] `GetChildCalendar` integrated response summary still contradicts its traced field model

The leading evidence sentence for `GetChildCalendar` in `evidence/responses/children-diary-files.json` at line 1223 says, “No other named response properties are attributed.” The same sentence is carried into the `GetChildCalendar` `x-static-response-evidence` in `models/responses.tsp` (around line 359). Both conflict with the same integrated record's following trace and nine-property field model: action callback `#26402` reads top-level `access` (line 1025977) and passes the unchanged body; reducer `#26394` reads `days`, `child_data`, `lock_date`, `comment_date`, `holidays`, `default_status`, `workday_weekend`, and `workday_holiday` directly from `action.data` (lines 1025725–1025747). The candidate source `evidence/guardian-batch/attendance.json` already records these root reads accurately.

**Required correction:** replace the stale “No other named response properties” summary in the integrated response evidence and emitted TypeSpec extension with wording consistent with the nine direct roots. Keep `days[]` item shape and all unobserved fields unknown; do not add composed calendar-cell fields.
